Schema design mostly agreed

Schema design pass, 2026-11-24. It covers the reaction file format, the Postgres tables, the arrow notation, and how answers are checked and given feedback.

The assistant's copy is docs/schema-design.md; the two are kept in sync. The summary decisions are also in the spec, §4.
Decided 2026-11-24
  • Q1 A resonance form of the expected state is accepted automatically. It is checked in the browser on the σ skeleton (§4), so nothing about resonance is stored in the file.
  • Q2 (revised) A mechanism is a graph of states. Correct routes may branch and must rejoin at the product.
  • Q3 An authored misconception beats a generic rule.
  • Q4 Fish-hooks need full bookkeeping (3 arrows for H-abstraction).
  • Acceptance is by result. Any legal, non-redundant set of arrows whose result matches the target state (up to symmetry and resonance) is correct. The old “alternatives” list is gone. In its place, partialArrowSets (optional) lists other complete arrow sets only so partial progress is recognised.
  • Naming: every name must be unambiguous to someone new to that part of the code. All keys below follow this, and §0 fixes each term to one meaning.

0 · Terms

Each term means exactly one thing in the docs, the JSON and the code.

2 · Atoms, loci and the arrow notation

A state's mappedSmiles is one dot-separated, fully atom-mapped, Kekulé SMILES. Arrows act on drawn π bonds, so there are no aromatic lower-case atoms. A hydrogen is an explicit mapped atom [H:n] only if it takes part in some step (or the author wants it drawn); the rest are implicit. Lone pairs follow from valence and charge. Radicals are bracket atoms with a missing H, e.g. [CH3:4].

LocusMeaning
lp O1A lone pair on O1. Pairs on one atom are equivalent, so they have no index.
rad C3The unpaired electron on C3.
σ C2-Br3A σ bond (either atom order; sigma also works).
π C5-O6A π bond: the second or third bond of a multiple bond.

An arrow is <source locus> -> <destination locus> for a pair, or ~> for a fish-hook. The notation is borrowed from synkit. The destination is where the electrons end up:

  • lp X — a lone pair on X (a bond breaks toward X)
  • σ X-Y — a new bond between atoms that were not bonded
  • π X-Y — an existing X–Y bond gains one order
  • rad X — fish-hook only: the electron becomes unpaired on X
Examples
SN2: lp O1 -> σ O1-C2, σ C2-Br3 -> lp Br3
H-abstraction: rad Br1 ~> σ Br1-H2, σ C3-H2 ~> σ Br1-H2, σ C3-H2 ~> rad C3

Parser and printer built

  • Printed form: σ/π symbols (sigma/pi are accepted when reading), bond atoms in ascending map-number order (σ C3-H2 prints as σ H2-C3), single spaces. Two ways of writing the same arrow become the same arrow.
  • Errors, checked in this order: malformed arrow, malformed locus, malformed atom label, one map number with two elements, a bond from an atom to itself, an arrow to itself, an unpaired electron in a pair arrow. The first three are pure syntax, and a test keeps the schema's arrow pattern in step with them. Checks that need the molecule (does O1 have a lone pair?) come with applying arrows.
  • Misconception patterns (wildcards, roles) are a separate grammar, built with the feedback pipeline.

Where the electrons can go coherence pass 2026-11-26

The learner picks a source, then a place: an atom, a bond, or a new bond drawn dashed between two atoms. One function, tapToDestinationLocus, says what a place means however it was chosen (tap, keyboard or pointing); the drawing lays out the same places and picks the nearest to the pointer. Learners and Create share it.

SourcePlaceDestination
lone pair / radical on Xatom Xrefused
lone pair / radical on Xatom Y not bonded to Xσ X-Y
lone pair / radical on Xatom Y bonded to X, or the bond X–Yπ X-Y
bond A–Batom A or Ba lone pair (or radical) on it
bond A–Bbond B–Cπ B-C
bond A–Batom Y bonded to one end (A)the 1,2-shift of B onto Y if one is offered; otherwise π A-Y
bond A–Batom Y bonded to neither or bothrefused: point at the new bond instead
bond A–Ba new bond A–Y or B–Yσ, if offered

New bonds offered go to atoms that can take one (electron-poor, positive, with a π bond, a radical, bonded to O/S/halogen, or a transferable H). To another molecule: always. Two bonds away: only a 1,2-shift onto an electron-poor atom or one with a single bond to a leaving group (not C=O). Three bonds away: never. Four or more: a ring closure, shown when drawn near.

Guards: the order the arrows are drawn in never matters (a test tries every order of every example step; the drawability check does the same for all content), and tests pin what common places mean (the cation in a hydride shift is the shift; the carbonyl carbon in enolate formation is the C=C π bond).

Step kind (stepKind): polar, radical or change (no arrows). The rule wrong-arrow-type fires when the learner's arrow type fits no step leaving the current state.

Graph rules (checked by the linter)

  1. Every state is reachable from the start, and every step's states exist.
  2. No loops. A reversible dead end is a plausible misconception, not a step.
  3. Product states (no step leaves them). The preferred route ends at the main product. Other routes rejoin it or end at an alternative product, reached only by accepted steps: a minor regioisomer, such as ortho beside para (revised 2026-11-26, item 10e). An alternative product needs a caption saying what it is (a warning). Only regioisomers by convention; E/Z and others wait until a reaction needs them. (Item 12: once states carry stereo, an alternative product may also be a stereoisomer.)
  4. Exactly one route made only of preferred steps.
  5. Two steps leaving one state must not reach resonance-equivalent states.
  6. Each step's canonical arrows and partial arrow sets reproduce its to-state.
  7. No misconception matches an arrow set that would be accepted.

4 · What counts as correct checked in the browser

  1. Each arrow is legal on the current state: the source holds the electrons, the destination is well formed, and the arrow type fits some step leaving the state.
  2. Apply the arrows and check the bookkeeping: octet/duet (H ≤ 2 e⁻, period 2 ≤ 8, period ≥ 3 up to 12). built All arrows of a step move their electrons at once. Electrons are counted, and formal charge is worked out from them, so electrons and charge can't be created or lost by mistake. An even number of nonbonding electrons is read as lone pairs, an odd number as one unpaired electron (triplet carbenes are out of scope).
  3. No redundant arrows: no group of arrows may together move no electrons, such as an arrow and its exact reverse. Removing such a group would leave the result unchanged, so a correct answer padded with one is not accepted, and redundant-arrow names the group. (Corrected while building: the first wording, “removing any one arrow must change the result”, can't catch a cancelling pair, because removing just one of the two does change the result.)
  4. Compare the result with each leaving step's to-state. They match when, after some skeleton symmetry:
    • the σ skeleton is the same (atoms, elements, σ-bonded pairs, H per atom);
    • each molecule has the same charge and the same number of unpaired electrons;
    • the result has no more charged atoms than the to-state.
    If only the last point fails, the result is a minor, charge-separated resonance form. The learner gets partial progress, minor-resonance-form: “right bonds, but this leaves C⁺ next to O⁻: push the O lone pair in too”.
  5. On a match, the learner moves to that step's to-state as the author drew it. If their drawing was a different resonance form, they see “valid resonance form — the next step uses this drawing”.
Why this is cheap. π and lone-pair arrows cannot change the σ skeleton. Conversely, take two drawings with the same skeleton, charge and unpaired electrons per molecule, which both pass the octet check. The electrons that differ flow along existing bonds, so the difference breaks down into paths of π/lone-pair arrows. No path can pass through an sp³ atom, which has no π bond or spare room in either drawing. So the test is one pass over atoms and bonds, in microseconds, with no RDKit and no list of resonance forms. Listing forms instead grows exponentially in the worst case (fused aromatics).

Skeleton symmetry is found by listing the reorderings of the current state's atoms that keep its σ skeleton (elements and H counts included). The molecules here are small: a tert-butyl group with every H drawn is about 1,300 reorderings. Above a safety cap of 10,000, the linter warns and the browser compares without symmetry.

A right product reached by nonsense arrows fails at point 1, 2 or 3. Point 4 compares the whole mapped skeleton, so arrows that move the wrong atoms also fail.

5 · Feedback

Order decided Q3 built

The validator returns an attempt assessment: correct (with the step taken), a misconception, a generic rule, partial progress, or wrong. Decided 2026-11-24: partial progress comes before the generic chemistry rules, because a correct but incomplete concerted step nearly always breaks one. For example, the first SN2 arrow alone gives carbon 10 electrons. First match wins:

  1. correct: the arrow type fits the step, the arrows apply, none are redundant, and the result matches;
  2. arrows that mean nothing (no such atom, no electrons there, or a destination not next to the source);
  3. authored misconceptions, in list order;
  4. partial progress, together with any rule the incomplete arrows break (below);
  5. generic rules, in this order: wrong arrow type, redundant arrows, reversed flow (an arrow drawn the other way round from a correct one), then the other arrow rules (octet, odd electrons in a bond…);
  6. wrong, with a generic “not this pathway” message.

locusKind           := lp | rad | σ | π | bond | *                   bond = σ or π
atomSelector        := O1 | O* (any O) | @nucleophile (a role) | *
  • Patterns refer to chemistry, e.g. lp @nucleophile -> @leavingGroup or π C5-O6 -> C5.
  • Patterns use the same skeleton symmetry as the answer, so an entry for H4 also fires for H5 and H6.
  • severity: wrong or plausible (valid pushing, but not a route this reaction accepts). In daily mode both cost an attempt; the wording differs.
  • Matching means “contains”, so extra correct arrows don't hide a misconception. The linter warns when an entry can never fire.

Partial progress

Both parts are shown (decided 2026-11-24). The assessment carries the progress and any rule the incomplete arrows break, so the screen can say: “Right so far — 1 more arrow, but carbon would have 10 electrons.” It counts as partial progress when the arrows match an authored message, are part of a known arrow set, or give a charge-separated resonance form of the expected structure.

  • Automatic: every learner arrow belongs to the canonical arrows or to a partial arrow set of some leaving step. The learner sees “Right so far — N more arrows”.
  • Why partialArrowSets exists: acceptance needs no list, but “right so far” compares with known complete sets. A learner half-way through a different valid set would otherwise be told “wrong” too early. The linter checks each listed set reproduces the step's to-state.
  • Authored messages (partialProgressMessages on the state): { "learnerArrows": ["lp O1 -> σ O1-C2"], "feedbackMessage": "Octet check: …" }. This replaces the automatic text when the learner's set matches exactly.
